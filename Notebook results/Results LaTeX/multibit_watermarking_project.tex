\subsubsection{Overview}\label{overview}

This notebook implements the multi-bit watermarking scheme proposed by
\textbf{Leroux et al.} (CVPR Workshop 2024), which builds upon
foundational ideas from \textbf{Adi et al.} (USENIX Security 2018).

\textbf{Core Idea:} We train a neural network to behave in a specific,
controllable way when presented with specially crafted \emph{trigger
inputs}. Each watermarked model instance responds differently to the
same set of triggers, encoding a unique binary signature (watermark).
This allows the model owner to:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Prove ownership} of a stolen model by querying it with trigger
  inputs.
\item
  \textbf{Trace the source} of a model leak to a specific user/device.
\end{enumerate}

\subsubsection{Why Black-Box?}\label{why-black-box}

No access to model weights is needed for verification - only the ability
to query the model and observe its predictions. This is realistic for
scenarios where a stolen model is deployed behind an API.

\subsection{3. Phase 2a: Encoding Scheme
Generation}\label{phase-2a-encoding-scheme-generation}

Following Leroux et al., we create a mapping
\(f: Y \rightarrow \{0, 1\}\) that assigns each class to a bit value.

\textbf{Procedure:} 1. Pass a subset of training samples through the
model and record the \textbf{logit} (pre-softmax) activations. 2.
Compute the \textbf{mean logit vector} for each class. 3. Apply
\textbf{K-means clustering} (K=2) on these mean vectors to split the
classes into two groups: bit ``0'' and bit ``1''.

The meaning of this is that classes with similar internal
representations will be grouped together, and the two groups will
correspond to semantically meaningful categories (e.g., vehicles
vs.~animals).

\subsection{4. Phase 2b: Trigger Input
Generation}\label{phase-2b-trigger-input-generation}

This is the most critical phase. We generate \textbf{K trigger inputs},
each positioned near the \textbf{decision boundary} between two classes
from different bit groups.

\textbf{For each trigger input:} 1. Randomly select one sample from a
bit-0 class and one from a bit-1 class. 2. Average them pixel-wise as
initialization. 3. Optimize the combined image via gradient descent
(model weights frozen) to minimize:

\[\mathcal{L}(x) = \text{ReLU}(k - Z_i(x)) + \text{ReLU}(k - Z_j(x)) + \sum_{t \neq i,j} Z_t(x)\]

where \(Z\) is the logit vector, \(i\) is a class from bit-0 group,
\(j\) from bit-1 group, and \(k\) is a threshold hyperparameter.

\textbf{Meaning:} We want the model to be equally confident about class
\(i\) and class \(j\) (i.e., the input sits right on the decision
boundary). Later, during embedding, we just need a tiny ``nudge'' to
push it to one side or the other.

\subsection{5. Phase 3: Signature
Embedding}\label{phase-3-signature-embedding}

Now we embed a specific watermark bitstring into a copy of the base
model.

\textbf{How it works:} For each trigger input, based on the desired bit:
- If the desired bit is 0, the target label is the bit-0 class from the
trigger pair. - If the desired bit is 1, the target label is the bit-1
class from the trigger pair.

We fine-tune the model on the original training data \textbf{combined}
with the trigger inputs (each assigned its target label). Since the
trigger inputs are already near the decision boundary, only a small
adjustment is needed (this is why embedding is fast).

\subsection{7. Conclusion}\label{conclusion}

\subsubsection{Summary of Results}\label{summary-of-results}

In this project, we implemented the \textbf{multi-bit black-box
watermarking scheme} proposed by Leroux et al.~(CVPR Workshop 2024). The
key findings are:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\item
  \textbf{Functionality Preservation:} Watermarked models maintain test
  accuracy close to the unwatermarked baseline, with minimal
  degradation.
\item
  \textbf{Multi-bit Capacity:} Using K=30 trigger inputs, we can
  generate up to \(2^{30} \approx 1\) billion unique watermarked model
  instances, each identifiable through the same set of trigger queries.
\item
  \textbf{Fast Embedding:} Watermark embedding takes only a few seconds
  to a few minutes per instance, making the scheme highly scalable for
  edge deployment scenarios.
\item
  \textbf{Robustness:} The watermark shows varying degrees of resilience
  against common removal attacks. Fine-tuning and pruning attacks tend
  to degrade the watermark alongside model accuracy, making aggressive
  removal self-defeating for the attacker.
\end{enumerate}

\subsubsection{Key Insight from the Security
Perspective}\label{key-insight-from-the-security-perspective}

The scheme exploits the fact that trigger inputs sit near the
\textbf{decision boundary} between two class groups. This makes it easy
to embed arbitrary bit patterns with minimal model modification, but
also means the watermark is inherently tied to the model's learned
decision surface. Attacks that significantly alter this surface will
also damage the model's primary functionality.

\subsubsection{Limitations \& Future
Work}\label{limitations-future-work}

\begin{itemize}
\tightlist
\item
  The watermark's robustness could be improved by incorporating
  \textbf{error-correcting codes} into the bitstring.
\item
  \textbf{Adversarial training} attacks pose a significant threat and
  deserve deeper investigation.
\item
  The approach could be extended to other modalities (NLP, audio) beyond
  image classification.
\end{itemize}
